## Running it

```bash
pip install -r requirements.txt

# generate a test bed (the real archive is not in this repo)
python tools/make_synthetic_archive.py archive.csv

# the measurement protocol -- this is the only source of accuracy numbers
python -m tbt backtest archive.csv --report report.txt

# train a deployable bundle (bootstraps the ledger on first run)
python -m tbt train archive.csv --out models --bootstrap-ledger

# score one tank; every scope answer is required
python -m tbt predict --diameter 32 --height 30 --material CS \
    --use-type "Fire Protection Storage Tank" --state MO \
    --construction yes --insulation no --insulation-erection no \
    --freight yes --taxable no --out models

# batch, archive audit, model status
python -m tbt score quotes.csv scored.xlsx --out models
python -m tbt audit archive.csv audit.xlsx
python -m tbt info --out models

# tests
python -m pytest tests -q
```

Retraining is a scheduled task: `python -m tbt train archive.csv --out models`.
It scores the new month into the ledger with the CURRENTLY DEPLOYED bundle and
only then retrains. That order is load-bearing; see below.

## The honesty note, which is the most important part of this file

**The real archive is not in this repository.** It is gitignored because it
contains customer names and real pricing, and it was never committed. Every
number produced during this build therefore comes from a SYNTHETIC archive
generated by `tools/make_synthetic_archive.py`.

What that means, precisely:

- The synthetic archive is calibrated to the documented structure of the real
  one: row and quote counts, the revision and multi-tank line structure, the
  accounting identities, component presence shares, price drift, the
  superlinear large-tank effect, the per-segment variance ordering and the
  ~173 partial quotes. The loader's validation accepts it and the protocol
  runs on it exactly as it would on the real file.
- Its irreducible noise was tuned so its floor is 4.60% mean APE, matching the
  documented estimate for the real archive. That makes the measured numbers
  comparable IN SCALE to the real 8.5% baseline.
- **It is not the real data-generating process.** A mean APE measured on it is
  a property of the noise this generator injects. It is NOT a prediction of
  accuracy on TBT's archive, and it must never be quoted as one.

What the synthetic runs legitimately establish:

1. The pipeline runs end to end, unattended, inside the stated runtime budget.
2. The harness measures what the spec says it measures, and the integrity
   tests catch the leakage and filtering mistakes they were written to catch.
3. The pipeline extracts nearly all of the signal that is there, measured as
   distance to a floor that is known exactly because it was constructed.
4. The refusal contract holds: every input the spec says must be refused is
   refused.

What only the real archive can establish: the actual mean APE, whether the
open experiments resolve the way the spec predicts, and whether the target of
8.0% is reachable. Running `python -m tbt backtest <real archive>` produces
that number and is the first thing to do when the file is available.

Two results from the synthetic runs that do NOT transfer, and should not be
read as evidence about the real archive:

- **The backbone-only result.** The spec predicted roughly 35-45% median with a
  top-5% bias near -50%. On the synthetic archive the backbone alone is far
  better than that, because the generator makes geometry more dominant than it
  appears to be in the real data. This says the synthetic archive is easier in
  the geometry dimension, not that the real backbone will behave this way.
- **The OPEN-2 physics experiment.** The generator's cost driver is a
  steel-weight-like quantity, deliberately built with different constants, a
  crane-class step and a rigging premium that the model's term does not
  contain. That keeps the experiment from being a tautology, but the outcome is
  still a test against a process this repository chose. Re-run it on the real
  archive before treating it as decided.

## Bugs found while building, and the guards now covering them

| Bug | Symptom | Guard |
|---|---|---|
| `variants=[] or DEFAULT` is falsy | The backbone-only increment silently trained the full production ensemble, so it would have reported a wrong "backbone alone" number | `test_empty_variant_list_means_backbone_only` |
| Tax table keyed on bare codes | `CA` is both California and Canada; a Canadian job could inherit the California rate | Keys are namespaced `state:` / `country:`; `test_us_state_does_not_inherit_a_country_rate` |
| US rows fell back to a national tax rate | A US row with an unfamiliar state got a silent average instead of the `TAXRATE` warning | Country fallback applies to non-US rows only |
| Package exported `estimate` over the module of the same name | `from tbt import estimate` returned the function, so the module was unreachable | Module renamed to `tbt/scoring.py` |
| Ledger round-trips through object dtype | `np.log` raised on ledger-derived residuals | Explicit numeric coercion in `conformal` and `ledger` |
| Generator padded rows by duplication | Identical quote keys received different price draws, which the duplicate-key validator correctly rejected | Generator builds to the target instead of padding |

## The things most likely to be broken by a well-meaning change

These are the load-bearing pieces. Each has a test; each is explained where it
lives.

1. **Scope is an input.** Five booleans, no defaults, no classifier. A blank
   returns `#SCOPE`. Adding a default is the single most likely regression and
   it will look like a usability improvement.
2. **Ledger before retrain.** `train()` scores the new rows with the deployed
   bundle and only then refits. Swap the order and the conformal bands collapse
   and the retransformation factor drifts to 1, while every number still looks
   plausible.
3. **One `usable` mask.** Fitting and scoring share it. Filtering one and not
   the other makes the model look better without being better.
4. **The ridge backbone.** It is a poor model alone and that is not the point.
   It is what lets the ensemble extrapolate past the largest tank it has seen.
5. **No random split anywhere.** The harness exposes none, and a test asserts
   the module contains no splitter and no `random_state` split parameter.
6. **`IS_TAXABLE` is not a price feature.** It gates the tax arithmetic only.
